# WoodyUi 数据目录迁移

Windows 安装版首次启动时，将 `%APPDATA%\AionUi` 中的配置、对话数据库、会话文件、待办事项和 Chromium 配置迁入 `%APPDATA%\WoodyUi`。安装目录及应用 ID 不变。开发模式继续使用原开发目录。

## 首次启动

1. 退出 Woody/AionUi，包括托盘和后台 AionCore。迁移不会强制结束这些进程。
2. 启动新版。程序先取得历史目录的单实例锁，随后备份并逐文件校验 SHA256。备份位于 `%APPDATA%\AionUi-backup-随机后缀\AionUi`。`incomplete` 子目录表示备份未完成，不能作为已验证备份使用。
3. 校验成功后，逐项迁移数据至 `WoodyUi`。迁移记录保存在 `%APPDATA%\.woodyui-data-migration.json`，用于恢复中断的迁移。
4. 旧目录保留 Electron 的锁文件，以及指向新目录的兼容引用。目录使用 junction，根目录文件使用硬链接。旧会话内的绝对路径仍可访问原文件。实际配置及对话数据位于 `WoodyUi\config`、`WoodyUi\aionui` 和 `WoodyUi\todo`。

不要手工删除旧 `AionUi` 兼容目录、其中的链接或迁移记录，也不要将它误认为另一份独立备份。根目录硬链接只兼容现有文件引用；某些 Chromium 根目录元数据在原子替换后可能独立更新，因此后续备份及使用都以 `WoodyUi` 为准。

两个独立的 `AionUi`、`WoodyUi` 目录同时存在时，程序停止迁移，不会合并或覆盖。备份失败、磁盘空间不足、文件被占用、校验不一致时也会停止启动，并保留数据。修复原因后重试；已经开始逐项迁移的情况会按记录继续。

## 备份与恢复

- 升级前及后续备份均应完全退出程序。新版备份整个 `WoodyUi`；迁移前备份整个 `AionUi`。包括数据库的 WAL/SHM 文件，不要只拷贝主数据库。
- 自动备份包含普通文件和目录，以及原有链接本身；链接指向的外部工作区、技能目录需要单独备份。Electron 的临时锁文件不进入备份。
- 恢复迁移前状态：完全退出程序，先将现有 `WoodyUi`、旧兼容目录和迁移记录分别改名保留，再将已验证备份中的 `AionUi` 复制回 `%APPDATA%\AionUi`。不要覆盖原目录或递归删除 junction 的目标。下次启动新版会重新备份和迁移。
- 恢复新版备份：完全退出程序，保留当前数据副本，按相同物理路径恢复 `WoodyUi`，并保留匹配的旧兼容目录和迁移记录。外部工作区需另行恢复。

## 开发验证

单元测试覆盖备份失败、内容变化、目录冲突、悬空技能链接、迁移中断恢复、旧路径引用和 E2E 隔离。Windows 还需使用真实 Electron 验证单实例锁持有期间可以迁移：其 `lockfile` 会阻止直接重命名整个旧目录，不能用 mock 锁替代这项验证。

`AIONUI_E2E_TEST=1` 必须同时指定 `AIONUI_E2E_USER_DATA_DIR`。这种启动方式完全跳过真实配置目录迁移。勿使用生产配置进行测试。
