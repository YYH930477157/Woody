# 跨中间消息保持运行信息缩进

## 问题

对话消息列表会把连续的 thinking 和工具摘要合并到一个可折叠的运行中信息区域。当前实现遇到任意其他消息就立即结束合并，因此上下文压缩提示、权限请求、代理状态或其他动作插入后，后续 thinking/tool 会创建新的摘要，显示时失去原来的缩进和连续性。

## 目标行为

- 同一轮助手回复中的 thinking 和工具摘要只使用一个活动摘要。
- 同一轮中间出现的权限、状态、提示或其他消息仍作为独立消息显示。
- 中间消息不会被活动摘要的折叠状态隐藏。
- 下一条右侧用户消息结束当前轮；之后的助手活动创建新的摘要。
- 保留现有活动摘要的展开/折叠、运行状态、工具数量、锚点和跳转行为。

## 方案

`mergeTurnActivities` 将活动摘要视为当前助手轮次的持久槽位，而不是连续消息的临时缓冲：

1. 第一个 thinking 或 tool summary 到来时，在当前时间线位置创建一个 `turn_activity_summary`。
2. 后续 thinking/tool 追加到同一个摘要的 `activities` 和 `sourceMessageIds`。
3. 非活动消息直接放回时间线，保持独立渲染；它们不会清空当前摘要。
4. `position === 'right'` 的消息作为用户轮边界，清空当前活动槽位。边界消息之后的活动会创建新的摘要。

摘要对象在当前 `mergeTurnActivities` 调用内同步填充，保持第一个活动的时间位置和现有排序行为。活动摘要只收集活动消息，不改变中间消息的可见性或交互。

## 测试

在 `messageList.dom.test.tsx` 增加回归测试，构造 thinking → 权限/状态 → tool summary → thinking → 用户消息的序列，断言：

- 输出只有一个活动摘要；
- 摘要按顺序包含全部 thinking/tool 活动；
- 权限和状态消息仍是独立输出项；
- 用户消息后新增的活动会创建新的摘要。
