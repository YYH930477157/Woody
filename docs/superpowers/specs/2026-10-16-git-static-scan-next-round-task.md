# Git 提交流程下一轮任务书

## 目标

补齐当前 Git 提交流程的自动化闭环：

1. AI 完成一轮代码修改后，扫描本次提交中已勾选的文件。
2. 扫描发现问题时，复用当前对话发起 AI 修复。
3. 修复后重新扫描，修复过程不得修改未勾选文件。
4. 扫描通过后，使用原工程执行编译验证。
5. AI 根据当前对话生成提交说明草稿，用户可以编辑后再提交。

## 已确认的交互与边界

- AI 修复复用当前对话，不创建独立的静态扫描专家会话。
- 提交流程只处理变更界面中已勾选的文件。
- AI 修复一旦修改未勾选文件，流程立即阻止提交并提示用户。
- 提交说明使用现有模板字段：
  - 修改原因
  - 修改范围
  - 修改方案
  - 影响评估
  - 测试步骤
- AI 生成的是可编辑草稿，用户确认后才执行 commit。

## 编译验证策略

- 项目根目录 `.woody/static-scan.json` 中的构建配置优先。
- 项目未配置构建命令时，自动探测 IAR 或 CMake。
- 同时探测到 IAR 和 CMake 时，必须由项目配置选定唯一构建配置，不能隐式选择。
- 编译失败时停止提交，保留扫描结果、编译输出和本地修改供用户处理。

## 现有基础

当前 `main` 已包含：

- 变更文件勾选和按选择提交。
- 分支显示与切换。
- clang-tidy / PC-lint 配置、执行和诊断解析。
- 扫描、修复、复扫、编译、commit、push 的工作流服务契约。
- 提交信息模板字段校验。
- push 失败时保留本地 commit 并支持重试。

## 待确认项

- 单次提交流程允许的自动修复轮数。
- 修复轮数用尽后，是否停留在确认页由用户手工处理并重新扫描。
- IAR 工程和 CMake 工程的自动探测规则及默认命令参数。
