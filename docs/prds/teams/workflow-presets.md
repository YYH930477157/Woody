# 工作流角色模板

新建团队时，可选择工作流模板和一个基础助手。选择模板仅预览流程；点击“确认创建”才会创建角色副本、保存角色规则并创建团队。

| 模板       | 阶段                                                            |
| ---------- | --------------------------------------------------------------- |
| 新功能开发 | 需求分析 → 方案设计 → 代码实施 → 测试验证 → 代码审查 → 交付汇总 |
| 缺陷修复   | 需求分析 → 代码实施 → 测试验证 → 代码审查 → 交付汇总            |
| 代码审查   | 需求分析 → 代码审查 → 交付汇总                                  |

首个角色兼任队长，接到用户目标后，通过已有团队工具识别成员、安排阶段、传递结果。创建团队本身不会发送任务或调用模型。

每个角色都要求交接输入、状态（passed / blocked / changes_requested）、产物路径或完整摘要、验证证据、未解决问题和下一负责人。会话 ID 本身不代替交接信息。修复流程要求先复现问题；审查流程不自动进入实施。测试或审查要求返工时，由队长安排实施、复测、复审，最多两轮后报告剩余阻塞。

## 配置与持久化

- 每次创建使用独立、可编辑的用户助手副本，不修改基础助手。副本使用“团队名 · 角色名”命名，在助手设置中管理。
- 副本继承基础助手的引擎、解析后的默认模型、能力、默认配置和现有规则，并附加角色约定。选择适合代码工作的基础助手，避免与角色职责冲突的原有规则。
- 规则使用无语言后缀的存储方式，切换界面语言仍能读取。角色约定要求使用用户语言回复。
- 角色准备失败会尝试删除本次新建的副本；清理失败会显示剩余 ID。未创建团队前不会返回不完整的角色列表。
- 团队创建失败后，保持弹窗并重试可复用已准备的角色。关闭弹窗后副本仍保留，可在助手设置管理或用于自定义团队。

## 能力边界

这是基于角色指令和现有 Team 任务、消息能力的协调模板。阶段检查、返工次数、角色职责由模型遵守，尚无引擎强制门禁、持久化阶段状态机、断点恢复或可视化流程编辑器。角色约定不授予或限制工具权限，实际权限沿用现有运行时机制。提交、推送、合并、部署及外部消息仍需遵循用户授权。

## 验证

单元测试覆盖角色模型配置继承、规则保存、部分失败清理、清理失败提示、模板阶段和不可用助手。弹窗测试覆盖无副作用预览、来源助手选择和创建失败后的重试。真实后端冒烟使用独立临时数据目录验证规则跨语言读取与六成员团队创建；不发送模型任务。
