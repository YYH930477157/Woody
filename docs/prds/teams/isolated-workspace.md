# 团队独立工作区

多个团队同时修改同一个 Git 仓库时，如果都在同一个文件夹里改，会互相覆盖文件、把对方改了一半的代码编译进去，提交时也分不开。独立工作区让每个团队用自己的 git worktree：一个和仓库同级的文件夹，检出一个新分支，与主文件夹共用同一份 `.git`。

## 新建团队

- 工作空间选在某个 Git 仓库内时，表单出现“独立工作区”开关，说明会从当前分支新建分支和同级文件夹。所选文件夹不在仓库里时不显示；分离 HEAD 或仓库没有提交时显示原因并不可开启。
- 当前文件夹有未提交或未跟踪的改动时提示：这些改动不会带到新工作区。
- 开启后点击“确认创建”，先建工作区，再准备角色、创建团队：
  - 分支 `team/<名称>`，文件夹 `<仓库名>-<名称>`，与仓库同级。名称只用 ASCII 字母、数字和 `-`（MinGW 不认非 ASCII 路径）；团队名没有可用字符时用时间，如 `team-20261115-224512`。重名时加 `-2`、`-3`。
  - 从当前提交新建，分支配置 `branch.<分支>.woodyBase` 记下要合并回的分支，也作为“这是 Woody 建的团队工作区”的标记。
  - 工作空间选的是仓库里的子文件夹时，团队工作空间是新工作区里的同一个子文件夹。
  - 团队的 `workspace_mode` 记为 `isolated`。AionCore 目前只保存这个字段，没有据此改变行为。
- 团队创建失败时保留已建好的工作区，重试会复用；换了工作空间再重试会删掉旧的、重新建。关闭弹窗时，删除还没用过（没有新提交、没有改动）的工作区和分支。

## 完成后合并、删除

团队工作区的 Git 面板顶部显示一条“团队工作区：分支 → 基础分支”，带领先/落后的提交数和两个按钮。其他仓库不显示。

**合并到基础分支**（团队工作区有未提交改动、进行中的合并，或没有新提交时不可用）：

1. 基础分支已在团队分支里：直接快进。
2. 两边都有新提交、没有冲突：在内存里生成合并提交（`git merge-tree --write-tree` + `commit-tree`，第一父提交是基础分支），再把基础分支快进到它。不碰任何文件夹的文件。
3. 有冲突（或 Git 版本低于 2.40）：把基础分支合并进团队工作区，冲突留在团队工作区，用“Git 历史”→“解决冲突”处理并提交；再点一次合并就只剩快进。
4. 快进时：如果基础分支在某个文件夹里检出，就在那个文件夹 `merge --ff-only`，那里有会被覆盖的未提交改动时 Git 拒绝，提示先提交或贮藏，基础分支不动；如果没有任何文件夹检出基础分支，只移动引用（带期望旧值的 `update-ref`）。

**删除工作区**：确认后删除文件夹和分支。

- 有未提交改动时不可用；有未跟踪文件时 Git 拒绝删除（被忽略的构建产物不影响）。
- 分支还有没合并的提交时，确认框写明会丢失几个提交。
- 使用这个工作区的团队之后无法继续工作，确认框提示先停止团队成员。文件被占用时删除失败，提示停止成员、关闭打开该文件夹的程序后重试。

所有操作都在同一个仓库锁（按 git common dir）下进行，与 Git 面板的其他操作互斥。

## 限制

- 子模块不会自动初始化；Git LFS 文件按仓库自身配置处理。
- 每个工作区是一份完整的源码，代码记忆需要单独索引；团队成员目前本来也用不了代码记忆。
- 开发板、串口等硬件只有一套，多个团队的烧录和串口验证仍需排队。
- 加密电脑上，worktree 的文件由 Git 写出，能否被 Woody 和索引器读取需要先实测。

## 验证

`tests/unit/sourceControl/workbench/mergeIntegration/teamWorktree.test.ts` 用真实 Git 仓库覆盖：命名与重名、子文件夹映射、分离 HEAD、快进、内存合并（第一父提交）、冲突转到团队工作区解决后再快进、未提交改动与基础文件夹本地改动的阻止、基础分支未检出时只移动引用、删除（已合并、未合并需确认、忽略文件不影响）、只丢弃未使用的工作区。界面测试覆盖开关显示条件、复用与替换、关闭时清理、团队以 `isolated` 模式和新路径创建，以及 Git 面板提示条的合并、冲突提示和删除确认。
